## 为什么需要它

把「帮我写个开题报告」丢给通用 AI，通常会得到这四种东西：

| 通用 AI 的常见产出 | 问题 |
|---|---|
| 一堆漂亮但空的套话 | 「随着……的不断发展，……越来越受到重视」——读完不知道你要研究什么 |
| 文献综述写成花名册 | 「张三(2018)认为……李四(2020)认为……」——没有分类、没有批判、没有缺口 |
| 编造的参考文献 | 作者真有，那篇文章不存在；或者 DOI、页码全是假的 |
| 硕博口径的臃肿结构 | 光文献综述就让你写 3000 字，本科根本用不上 |

这个 Skill 就是来解决这四件事的。

## 它做什么

**一句话**：交互式逐节引导 → 学术性与逻辑性双五项诊断 → 严格执行学校格式规范 → 输出可直接提交的 `.docx`。

### 八节结构（本科口径）

| 节 | 标题 | 字数 |
|---|---|---|
| 一 | 选题背景与问题提出 | 800–1200 |
| 二 | 研究意义 | 300–500 |
| 三 | 文献综述 | 1200–1800 |
| 四 | 核心概念界定与理论基础 | 500–800 |
| 五 | 研究目标与研究内容 | 500–800 |
| 六 | 研究思路与研究方法 | 600–900 |
| 七 | 研究重难点、创新点与可行性 | 300–500 |
| 八 | 研究进度安排与预期成果 | 250–400 |

### 六条硬红线

1. **不编造文献**——不生成不存在的文献、DOI、页码、学者观点。不确定就说「我不确定，建议你核实」，并告诉去哪核实
2. **不编造数据**——不替你虚构问卷回收率、访谈人数、课堂观察记录
3. **不夸夸其谈**——没有「你一定能行」，反馈只落到句子、段落、逻辑节点
4. **不 PUA**——纠错只针对文本，不针对人
5. **客观辩证**——指出问题必给修改建议，否定观点必给替代方案
6. **格式刚性**——每次输出附「格式自检说明」

### 质量闸门：学术性五项 + 逻辑性五项

- **学术性**：问题真实性 / 概念清晰性 / 证据支撑性 / 结论超越性 / 方法适切性
- **逻辑性**：论点-论据-论证闭环 / 段落过渡 / 章节 MECE / 首尾呼应 / 标题即承诺

十项过完才进入下一节。给你的反馈统一标 `【P0】必须改` / `【P1】建议改`。

## 格式规范（已写进生成脚本）

默认采用**人文社科类本科毕业论文的常见格式口径**（不含任何特定学校信息），
**只要你提供自己学校的模板或规范，就以你的学校为准**，本文件仅作缺省值：

- 正文：宋体小四 / Times New Roman 小四，两端对齐，首行缩进 2 字符，**行距固定值 20 磅**
- 一级标题：黑体三号居中，段前段后各空 1 行，序号「一、」
- 二级标题：黑体小三，序号「（一）」；三级黑体四号「1.」；四级黑体小四「（1）」
- 封面临摹：题目小二小标宋居中，学院/专业/年级/姓名/学号/指导教师小三楷体
- 图表：图名在图下方、表名在表上方，五号宋体，全文连续编号
- 参考文献：五号宋体，顺序编码制 `[1]`，悬挂缩进 2 字符，**GB/T 7714-2015**

## 安装

### 方式一：手动（30 秒）

把整个文件夹复制到你的用户级技能目录：

```bash
# WorkBuddy / CodeBuddy（Windows）
C:\Users\<你的用户名>\.workbuddy\skills\thesis-proposal-ug\

# Claude Code
~/.claude/skills/thesis-proposal-ug/
```

```bash
git clone https://github.com/cfghftgyrty-jpg/thesis-proposal-ug.git
cp -r thesis-proposal-ug ~/.workbuddy/skills/    # Windows 上用资源管理器复制即可
```

## 使用

装好后，直接对 AI 说：

> **「我要写开题报告」**

它会一次性问你六件事：当前阶段 / 题目或方向 / 学院专业年级 / 有无实习现场 / 已有材料 / 学校时间节点。

如果你还停留在「我想写小学语文阅读教学」这种**领域**层面，它会停下来追问三问：

1. 你在教育现场观察到的**具体**现象是什么？
2. 你打算用什么**理论视角**解释它？
3. 你的**研究对象和边界**是什么？

答不上来就不往下走——因为答不上来的题目，写到第三章一定会崩。

确认完就一节一节磨：它先问你的想法 → 生成完整段落 → 你确认或修改 → 才进下一节。全程回看前面已确认的内容，前后矛盾会主动拦你。

### 生成 Word 文档

八节都确认后：

```bash
python scripts/generate_docx.py --output 开题报告.docx --data content.json
```

脚本只接受 `--output` 和 `--data` 两个参数，题目、作者等信息全写在 JSON 里。
直接复制 `scripts/sample.json` 改内容即可当模板。

依赖：`pip install python-docx`

## 适配你自己的学校

默认规范是**人文社科类本科的常见口径**，不绑定任何学校。**换成你们学校只需要两步**：

1. 改 `references/format_spec.md`——字体、字号、行距、标题序号、参考文献规则
2. 改 `scripts/generate_docx.py` 顶部的常量——`PT_XIAOSI`、`LINE_EXACT_20`、`BODY_INDENT`、标题字号表

有学校模板的话**优先遵循模板**。SKILL.md 里也写了这条：用户的学校要求 > 本技能的缺省值。

## 已知边界

生成脚本**不自动处理**（需在 Word 中手工完成）：

- 脚注（引用 → 插入脚注）
- 自动目录（引用 → 目录 → 自动目录）
- 罗马数字页码分节
- 原创性声明 / 使用授权声明页

另外：它不代你检索知网、万方等付费数据库，只给检索式和筛选策略——**文献必须是你自己读过的**。

## 学术诚信

这个 Skill 的定位是**脚手架，不是枪手**。它帮你把「想不清楚」变成「想清楚了并写出来」，但：

- 不生成你不曾读过的文献
- 不生成你没做过的调研数据
- 产出的每一节都需要你逐句审过、改成自己的话

用它写出来的东西，最终责任在你。这也是技能里那六条硬红线存在的原因。
